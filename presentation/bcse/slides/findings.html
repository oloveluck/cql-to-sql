Conclusions

The engine computes the measure correctly

All 19 hand-built members match. Every difference from the answer key on 1,000 members has a known cause.

How data records care decides the rate

The same clinical records score 36.1% as delivered and 60.4% with mammograms sent as test results. Claims-style data: 50.0%.

Expected results need checking too

The answer key was wrong for 8 members; we wrote these up, with the records, for its author.

A database query can match the engine

Identical results on the simplified measure. The full measure needs the translator to handle NCQA’s shared building blocks.

Next: extend the translator and run Method B on all three populations · release the engine bug fix · build test data in insurance-claims style.

Four conclusions. First, Method A computes NCQA's measure correctly: it matches every hand-built member, and every disagreement with the answer key has a known cause. Second, and most useful for anyone doing quality reporting: the rate depends on how the data records care. Clinical records lose screenings NCQA's rules cannot see; the same mammograms sent as test results restore the expected rate, and claims-style data runs cleanly. Third, expected results are data too, and can be wrong. Fourth, Method B, the database query, reproduces the engine exactly where it can translate today; the full measure needs the translator to handle the building blocks NCQA shares across its measures.
